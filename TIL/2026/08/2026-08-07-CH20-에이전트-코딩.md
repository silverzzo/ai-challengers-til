# CH20 (에이전트 코딩)

## 📝 오늘 배운 내용 요약

1-1. 에이전트 코딩

**에이전트 코딩**

`사용자가 자연어로 원하는 기능과 조건을 설명하면, 코딩 에이전트가 계획을 세우고 실제 파일을 생성·수정하는 방식`

```plain text
사용자 지시
→ 작업 계획
→ 파일 생성
→ 코드 작성
→ 수정
→ 검토
```

일반적인 AI 채팅은 코드를 답변으로 보여주는 경우가 많지만, 코딩 에이전트는 실제 프로젝트 폴더의 파일을 직접 만들고 수정할 수 있다.

```plain text
일반 AI 채팅
→ 코드 설명·코드 출력

코딩 에이전트
→ 프로젝트 파일 직접 생성·수정
```

2-1. 좋은 제작 지시

처음 프로젝트를 만들 때는 다음 내용을 구체적으로 전달한다.

```plain text
목적
→ 무엇을 만들 것인가?

산출물
→ 어떤 파일을 만들 것인가?

제약조건
→ 어떤 기술을 사용하거나 사용하지 않을 것인가?

기능·디자인
→ 어떤 기능과 화면이 필요한가?
```

예시

```plain text
현재 빈 폴더에
'오늘의 습관'이라는 습관 관리 웹앱을 만들어줘.

기술 조건
- HTML, CSS, JavaScript만 사용
- React, Node.js, npm, 외부 라이브러리 사용 금지
- index.html을 더블클릭하면 실행
- 코드를 답변으로만 보여주지 말고 실제 파일 생성

폴더 구조
- index.html
- css/style.css
- js/app.js
- README.md
```

```plain text
지시가 구체적
→ 에이전트가 선택해야 할 부분 감소
→ 원하는 방향에 가까운 결과
```

---

웹앱을 요청할 때는 필요한 기능을 번호로 나누어 전달하면 누락을 줄일 수 있다.

```plain text
핵심 기능
1. 새로운 습관 추가
2. 완료 여부 체크
3. 습관 삭제
4. 달성률 표시
5. 완료 개수 표시
6. 새로고침 후에도 기록 유지
```

기본 데이터도 함께 지정할 수 있다.

```plain text
기본 습관
- 물 8잔 마시기
- 30분 운동하기
- 책 10페이지 읽기
```

```plain text
기능 요구
+
초기 데이터
+
디자인 요구
→ 첫 결과의 완성도 향상
```

4-1. 왜 제약조건이 필요한가?

에이전트에게 기술 선택을 완전히 맡기면 설치가 필요한 React, Node.js 등의 구조를 만들 수 있다.

따라서 실행 환경을 먼저 제한한다.

```plain text
- HTML, CSS, JavaScript만 사용
- React 사용 금지
- Node.js 사용 금지
- npm 사용 금지
- 외부 라이브러리 사용 금지
- index.html 더블클릭으로 실행 가능
```

```plain text
제약 없음
→ 설치가 필요한 프로젝트가 생성될 수 있음

제약 있음
→ 초보자가 바로 실행 가능한 형태로 제한
```

특히 실습에서는 **결과물이 실제로 실행 가능한 조건**을 프롬프트에 포함하는 것이 중요하다.

---

디자인 역시 코드를 직접 수정하지 않고 요구사항으로 전달할 수 있다.

```plain text
디자인
- 스마트폰 앱처럼 구성
- 상단에 오늘 날짜와 인사말
- 중앙에 달성률 표시
- 습관은 카드 형태
- 밝고 깔끔한 디자인
- 완료한 습관은 색상과 취소선으로 구분
- 모바일과 PC 모두 반응형
```

```plain text
좋지 않은 지시
→ 예쁘게 만들어줘

개선된 지시
→ 색상, 배치, 분위기, 반응형 여부를 구체적으로 지정
```

---

에이전트가 완료했다고 말해도 실제로 직접 확인해야 한다.

기본 확인 항목

```plain text
파일이 생성되었는가?
→ index.html, css, js 등 확인

실행되는가?
→ index.html 직접 실행

기능이 동작하는가?
→ 추가·체크·삭제 테스트

데이터가 유지되는가?
→ 새로고침 후 확인
```

```plain text
에이전트의 "완료"
≠ 실제로 정상 동작함

직접 실행과 테스트
→ 최종 확인
```

7-1. 같은 프로젝트에 이어서 요청

프로젝트를 처음부터 다시 만들 필요 없이 같은 대화에서 수정 요청을 이어갈 수 있다.

```plain text
현재 기능은 모두 유지하면서
다음 내용을 수정해줘.

1. 전체 색상을 민트색과 보라색으로 변경
2. 완료 시 애니메이션 추가
3. 모든 습관 완료 시 축하 효과
4. 빈 습관 등록 방지
5. Enter 키로도 습관 추가
```

여기서 중요한 문구

```plain text
"현재 기능은 모두 유지하면서"
```

이 문구는 기존 기능을 유지해야 한다는 조건을 먼저 전달한다.

```plain text
수정 요청
→ 바꿀 것만 말함
→ 기존 기능이 깨질 수 있음

현재 기능 유지 명시
→ 기존 동작을 보존하면서 수정
```

`사용자 요청 → 실행 → 결과 확인 → 추가 요청 → 다시 수정하는 반복 과정`

```plain text

↓

↓
수정 요청
↓
기능 추가
↓
다시 확인
↓

```

에이전트 코딩에서는 처음부터 완벽한 결과를 얻으려 하기보다 작은 단위로 수정하며 완성도를 높일 수 있다.

기존 프로젝트에 새로운 기능을 추가할 수도 있다.

```plain text

- 기록은 localStorage에 저장
- 날짜 처리 오류가 없는지 확인

```

10-1. localStorage

**localStorage**

`브라우저에 데이터를 저장하여 새로고침이나 재실행 후에도 값을 유지하는 기능`

```plain text
localStorage.setItem(
  "habits",
  JSON.stringify(habits)
);
```

저장된 데이터 가져오기

```plain text
const habits =
  JSON.parse(
    localStorage.getItem("habits")
  ) || [];
```

- `setItem()` : 데이터 저장
- `getItem()` : 데이터 불러오기
- `JSON.stringify()` : 객체·배열을 문자열로 변환
- `JSON.parse()` : 문자열을 다시 객체·배열로 변환
```plain text
JavaScript 배열
→ JSON 문자열
→ localStorage 저장

localStorage 데이터
→ JSON.parse()
→ JavaScript 배열 복원
```

로그인이나 서버가 없는 간단한 웹앱에서 상태를 저장할 때 사용할 수 있다.

---

습관 앱처럼 날짜에 따라 상태가 달라지는 기능은 날짜 처리 조건을 명확하게 전달해야 한다.

```plain text
- 오늘 날짜의 체크 상태 저장
- 날짜가 변경되면 체크 상태 초기화
- 이전 기록은 통계용으로 유지
- 연속 달성일 계산 확인
```

```plain text
const today =
  new Date().toISOString().slice(0, 10);
```

날짜를 문자열 형태로 저장해 마지막 사용 날짜와 비교할 수 있다.

```plain text
저장된 날짜 == 오늘
→ 기존 체크 상태 사용

저장된 날짜 != 오늘
→ 오늘 체크 상태 초기화
```

※ 날짜와 시간대 관련 기능은 오류가 생기기 쉬우므로 별도로 점검하도록 요청하는 것이 좋다.

---

기존 앱에 새로운 화면이나 영역을 추가할 수도 있다.

```plain text
현재 앱 하단에
이번 주 기록 영역을 추가해줘.

- 최근 7일 표시
- 날짜별 달성률을 세로 막대그래프로 표현
- 외부 차트 라이브러리 사용 금지
- 오늘 날짜 강조
- 기록이 없는 날은 0%
```

외부 라이브러리 없이 HTML과 CSS만으로 간단한 막대그래프를 만들 수 있다.

```plain text
<div class="bar">
  <div
    class="bar-value"
    style="height: 70%">
  </div>
</div>
```

```plain text
달성률 70%
→ 막대 높이 70%

달성률 0%
→ 막대 높이 0%
```

13-1. 전체 점검 요청

구현뿐 아니라 프로젝트 검토도 에이전트에게 요청할 수 있다.

```plain text
현재 프로젝트를 전체적으로 점검해줘.

1. 습관 추가·완료·삭제 기능 확인
2. 새로고침 후 데이터 유지 확인
3. 날짜 변경 시 초기화 확인
4. 연속 달성일 계산 확인
5. 주간 통계 확인
6. 모바일 화면 확인
7. 브라우저 콘솔 오류 확인

문제가 있다면 직접 수정해줘.
```

```plain text
구현 위임
→ 기능 만들기

검토 위임
→ 오류와 누락 찾기

수정 위임
→ 발견한 문제 직접 수정
```

---

에이전트에게 검토까지 맡길 수 있지만 최종 확인은 사람이 해야 한다.

세 가지 관문

```plain text
1. 돌아가는가?
2. 요구와 맞는가?
3. 이상한 곳은 없는가?
```

직접 테스트

```plain text
습관 추가
→ 완료 체크
→ 삭제
→ 새로고침
→ 통계 확인
```

```plain text
에이전트 검토 결과
→ 참고

직접 실행 결과
→ 최종 판단
```

---

```plain text
어시스턴트
→ "이 코드를 사용하세요"
```

에이전트의 핵심 차이는 **답을 주는 것에서 끝나지 않고 실제 작업까지 수행한다는 점**이다.

16-1. 주제 정하기

에이전트 코딩에서는 사용자가 원하는 주제를 직접 선택할 수 있다.

예시

- 자기소개 페이지
- 최애 소개 페이지
- 미니 게임
- D-day 계산기
- 뽀모도로 타이머
- 랜덤 점심 추천기
- 간단한 퀴즈
초보자의 프로젝트는 다음 조건을 만족하면 좋다.

```plain text
서버 필요 없음
로그인 필요 없음
외부 API 필요 없음
버튼이나 입력 기능 존재
핵심 기능 2~3개
50분 안에 만들 수 있는 수준
```

---

무엇을 만들지 생각나지 않으면 아이디어를 정하는 과정도 AI에게 요청할 수 있다.

```plain text
나는 VS Code와 Codex를 처음 사용하는 초보자야.

50분 안에 만들 수 있는
간단하지만 실제로 작동하는 웹페이지 아이디어를 추천해줘.

조건
- HTML, CSS, JavaScript만 사용
- 외부 라이브러리 사용 금지

- 핵심 기능은 2~3개
```

결과 형식도 지정한다.

```plain text
1. 아이디어 5개
2. 핵심 기능 3개
3. 난이도
4. 가장 적합한 아이디어 추천
5. Codex에 넣을 제작 지시문
```

```plain text
아이디어 생성
→ 주제 선택
→ 제작 프롬프트 생성
→ Codex에 전달
```

18-1. 메타 프롬프팅

**메타 프롬프팅**

`AI에게 작업 자체가 아니라 다른 AI에게 전달할 프롬프트를 작성하도록 요청하는 방식`

```plain text
나 랜덤 점심 추천기를 만들고 싶은데,
코딩 에이전트에게 시키려면
어떻게 지시해야 하는지
빠짐없는 제작 지시문을 작성해줘.
```

```plain text
사용자
→ ChatGPT에게 프롬프트 제작 요청
→ 완성된 지시문
→ Codex에 전달
→ 프로젝트 생성
```

프롬프트 작성 자체가 어렵다면 프롬프트 작성도 AI에게 위임할 수 있다.

---

```plain text
[목적]
○○한 웹페이지를 만들어줘.

[산출물]
- 파일 구조는 네가 적절히 정해줘.
- index.html을 더블클릭하면 바로 실행되게 해줘.

[제약조건]
- HTML, CSS, JavaScript만 사용
- React, Node.js, npm, 외부 라이브러리 사용 금지
- 코드를 답변으로만 보여주지 말고 실제 파일 생성

[내용/디자인 요구]
- ____________________________
- ____________________________
- ____________________________
```

```plain text
목적
+
산출물
+
제약
+
기능·디자인
→ 기본 제작 지시문
```

---

처음부터 완벽하게 만들려고 하면 시간 안에 결과물을 완성하기 어렵다.

```plain text
1차 목표
→ index.html이 실행됨

2차 목표
→ 핵심 기능 동작

3차 목표
→ 디자인 개선

4차 목표
→ 애니메이션·추가 기능
```

```plain text
완벽한 첫 결과
X

작동하는 첫 결과
→ 수정하면서 개선
```

에이전트 코딩에서는 작은 **MVP**를 먼저 만든 뒤 반복적으로 개선하는 방식이 효율적이다.

```plain text
새로운 결과가 나오도록 기능을 추가해줘.
```

21-4. 반응형 수정

```plain text
현재 기능은 모두 유지하면서
휴대폰 화면에서도 깨지지 않도록
반응형 디자인을 점검하고 수정해줘.
```

21-5. 세부 수정

```plain text
현재 기능은 모두 유지하면서
제목은 더 크게 만들고
결과 영역은 가운데 정렬해줘.
```

---

22-1. 수정 루프

같은 문제를 여러 번 수정해도 계속 결과가 이상해지는 경우가 있다.

```plain text
수정 요청
→ 다른 부분이 깨짐
→ 다시 수정
→ 또 다른 부분이 깨짐
→ 반복
```

이런 상황에서는 작은 수정 요청을 계속하기보다 원하는 최종 모습을 다시 설명하는 것이 좋다.

```plain text
지금까지 수정 요청이 꼬인 것 같아.

통계 영역을 처음 상태로 되돌리고,
다음 요구사항을 기준으로 다시 만들어줘.

- ...
- ...
- ...
```

```plain text
부분 수정이 계속 실패
→ 최종 요구사항을 다시 정리
→ 해당 영역을 다시 구현
```

---

프로젝트 파일이 남아 있으면 나중에 같은 폴더를 다시 열어 작업을 이어갈 수 있다.

```plain text
프로젝트 폴더 저장
→ VS Code에서 다시 열기
→ 기존 파일 확인
→ 새로운 수정 요청
```

즉, 한 번의 대화로 끝나는 것이 아니라 프로젝트를 계속 발전시킬 수 있다.

---

Codex를 사용할 수 없는 경우 일반 AI 채팅으로도 웹페이지를 만들 수 있다.

```plain text
HTML/CSS/JavaScript를
모두 포함한 index.html 파일 하나로 만들어줘.
```

하지만 일반 웹 채팅에서는

```plain text
AI가 코드 생성
→ 사용자가 코드 복사
→ 메모장에 붙여넣기
→ 파일 저장
→ 수정할 때 다시 전체 코드 복사
```

코딩 에이전트에서는

```plain text
AI가 코드 생성
→ 파일 직접 생성
→ 기존 파일 직접 수정
→ 사용자는 실행과 검증 중심
```

이 차이가 어시스턴트와 에이전트의 가장 큰 차이 중 하나다.

---

```plain text
만들고 싶은 것 결정
↓
목적·산출물·제약·기능 작성
↓
코딩 에이전트에게 위임
↓
실제 파일 생성
↓
브라우저에서 직접 실행
↓
기능 테스트
↓
"현재 기능은 유지하면서" 수정 요청
↓
새로운 기능 추가
↓
전체 검토 요청
↓
사람이 마지막으로 직접 검증
```

## 💭 오늘의 회고

**배운 점**

- 에이전트 코딩은 자연어 지시를 바탕으로 AI가 실제 프로젝트 파일을 생성하고 수정하는 방식
- 코딩을 직접 하지 않아도 목적과 요구사항을 명확하게 설명하면 웹앱을 만들 수 있음
- 첫 제작 지시에는 `목적`, `산출물`, `제약조건`, `기능·디자인 요구`를 포함
- 기술 제약을 작성하지 않으면 설치가 필요한 프레임워크를 사용할 수 있음
- 초보자 실습에서는 HTML, CSS, JavaScript만 사용하도록 제한하면 실행하기 쉬움
- `index.html` 더블클릭으로 실행 가능하도록 요구하면 별도의 서버 없이 확인 가능
- 기능 요구사항은 번호로 나누어 작성하면 누락을 줄일 수 있음
- 디자인도 색상, 분위기, 배치와 반응형 여부를 자연어로 지정 가능
- `localStorage`를 이용하면 브라우저를 새로고침해도 데이터를 유지할 수 있음
- 객체와 배열은 `JSON.stringify()`로 저장하고 `JSON.parse()`로 복원
- 날짜 기반 앱에서는 날짜 변경, 상태 초기화와 기록 유지 조건을 별도로 점검해야 함
- 같은 프로젝트에서는 새로운 채팅보다 기존 작업에 이어서 수정 요청 가능
- 수정 요청은 **“현재 기능은 모두 유지하면서”**로 시작하면 기존 기능이 깨지는 것을 줄일 수 있음
- 에이전트 루프는 `요청 → 실행 → 확인 → 수정 → 재확인`의 반복 구조
- 첫 결과를 완벽하게 만들기보다 실행 가능한 MVP를 먼저 만드는 것이 효율적
- 새로운 기능이나 통계 화면도 자연어 요청으로 추가 가능
- 외부 라이브러리 없이 HTML과 CSS만으로 간단한 그래프와 애니메이션 구현 가능
- 구현뿐 아니라 오류 검사와 프로젝트 전체 검토도 에이전트에게 위임 가능
- 에이전트가 검토했다고 해도 실제 동작 여부는 사람이 직접 확인해야 함
- 최종 검증 기준은 `돌아가는가`, `요구와 맞는가`, `이상한 곳은 없는가`
- 일반 AI 어시스턴트는 주로 코드를 답변으로 제공하고, 코딩 에이전트는 파일 생성과 수정까지 직접 수행
- 만들고 싶은 주제가 없으면 아이디어 추천 과정도 생성형 AI에 위임 가능
- 메타 프롬프팅은 코딩 에이전트에게 전달할 제작 프롬프트 자체를 AI에게 작성시키는 방법
- 자유 빌드에서는 서버·로그인·외부 API가 필요 없는 작은 프로젝트가 초보자에게 적합
- 기능은 처음에 2~3개 정도로 제한하고 작동한 뒤 확장하는 것이 좋음
- 같은 수정이 반복해서 실패하면 작은 수정 요청을 계속하기보다 원하는 최종 모습을 다시 설명
- 프로젝트 폴더를 보관하면 나중에 다시 열어 이어서 개발 가능
- 에이전트 코딩에서 사용자의 역할은 코드를 모두 직접 작성하는 것보다 **무엇을 만들지 정의하고, 결과를 검증하고, 다음 지시를 결정하는 것**에 가까움
