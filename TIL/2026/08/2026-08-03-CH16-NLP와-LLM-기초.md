1-1. NLP

**NLP Natural Language Processing**

`사람이 사용하는 언어를 컴퓨터가 이해하고 생성하도록 만드는 기술`

대표적인 NLP 작업

- 번역 : 한 언어를 다른 언어로 변환
- 텍스트 분류 : 문장을 정해진 범주로 분류
- 감성 분석 : 문장이 긍정인지 부정인지 판단
- 요약 : 긴 문서의 핵심 내용 추출
- 질의응답 : 질문에 맞는 답변 생성
- 텍스트 생성 : 주어진 문장 뒤의 내용 생성
```plain text
사람의 문장
→ 컴퓨터가 처리할 수 있는 숫자로 변환
→ 문장의 의미와 관계 학습
→ 분류·번역·요약·생성
```

1-2. 컴퓨터가 문자를 보는 방식

컴퓨터는 문자를 내부적으로 숫자로 저장한다.

```python
text = "NEBULA 최고"

for ch in text:
    print(f"{ch} → {ord(ch)}")

print([ord(ch) for ch in text])
```

- `ord()` : 문자 하나를 유니코드 숫자로 변환
- `chr()` : 유니코드 숫자를 문자로 변환
하지만 문자 코드만으로는 문장의 의미를 알 수 없다.

```plain text
문자 코드
→ 문자를 구분하는 숫자

NLP에서 필요한 숫자
→ 단어의 의미와 문맥을 담은 숫자
```

NLP의 핵심은 문자를 단순한 숫자가 아니라 **의미 있는 숫자 표현**으로 변환하는 것이다.

2-1. 감성 분석

**감성 분석 Sentiment Analysis**

`문장에 포함된 감정이나 의견을 긍정·부정 등으로 분류하는 작업`

가장 단순한 방식은 긍정 단어와 부정 단어의 개수를 비교하는 것이다.

```python
positive_words = [
    "미쳤다", "최고", "역대급", "소름",
    "masterpiece", "stunning", "best", "wow"
]

negative_words = [
    "실망", "별로", "아쉽다", "아깝다",
    "disappointed", "worst", "boring", "ruined"
]
```

```python
def sentiment_v1(comment):
    text = comment.lower()

    pos = sum(
        1 for word in positive_words
        if word in text
    )

    neg = sum(
        1 for word in negative_words
        if word in text
    )

    if pos > neg:
        return "긍정"
    elif neg > pos:
        return "부정"
    else:
        return "중립"
```

```python
for comment in fan_comments[:3]:
    result = sentiment_v1(comment)
    print(result, comment)
```

2-3. 규칙 기반 방식의 한계

규칙 기반 모델은 사전에 등록된 단어만 확인한다.

```plain text
"Not bad at all"
→ bad가 포함됨
→ 부정으로 잘못 판단할 수 있음

"기대 안 했는데 역대급"
→ 부정 표현과 긍정 표현이 함께 존재
→ 단순 단어 개수로 문맥을 해석하기 어려움
```

주요 한계

- 새로운 단어나 신조어 처리 어려움
- 부정어의 범위 판단 어려움
- 반어법과 비꼬는 표현 이해 불가
- 단어가 등장한 순서와 문맥을 고려하지 않음
- 사전을 사람이 계속 관리해야 함
```plain text
규칙 기반
→ 단어가 있는지만 확인

언어 모델
→ 단어가 어떤 문맥에서 사용됐는지 학습
```

8-1. 임베딩

**임베딩 Embedding**

`단어나 문장을 의미를 담은 여러 개의 실수 좌표로 표현하는 방법`

```plain text
단어
→ 고차원 벡터
→ 의미가 비슷한 단어는 가까운 위치
```

예시

```plain text
music  → [0.21, -0.34, 0.82, ...]
song   → [0.19, -0.31, 0.79, ...]
pizza  → [-0.62, 0.51, -0.14, ...]
```

`music`과 `song`은 의미가 비슷하기 때문에 벡터 공간에서도 가까운 위치에 존재할 수 있다.

8-2. GloVe

**GloVe**

`단어가 여러 문장에서 함께 등장하는 통계를 이용해 학습한 단어 임베딩`

```python
import gensim.downloader as api

glove = api.load(
    "glove-wiki-gigaword-50"
)
```

```python
print(
```

- 단어 하나를 50개의 실수로 표현
- 하나의 단어가 50차원 공간의 한 점이 됨
- 각 숫자 하나를 직접 해석하기보다 전체 벡터의 관계를 이용

9-1. 단어 연산

임베딩에서는 벡터의 덧셈과 뺄셈으로 의미 관계를 표현할 수 있다.

```python
result = glove.most_similar(
    positive=["king", "woman"],
    negative=["man"],
    topn=3
)

print(result)
```

```plain text
king - man + woman
→ queen과 가까운 벡터
```

함수로 작성

```python
def word_math(positive, negative):
    return glove.most_similar(
        positive=positive,
        negative=negative,
        topn=3
    )
```

```python
print(
    word_math(
        ["paris", "korea"],
        ["france"]
    )
)
```

※ 모든 단어 관계가 정확히 계산되는 것은 아니며 임베딩 학습 데이터의 영향을 받음

9-2. PCA로 임베딩 시각화

50차원 벡터는 화면에 직접 표현하기 어렵기 때문에 PCA로 2차원까지 줄일 수 있다.

```python
words = [
```


10-2. Attention

**Attention**

`문장의 각 토큰이 다른 토큰을 얼마나 중요하게 참고할지 계산하는 방식`

```plain text
"The concert was not boring"

boring
→ not을 중요하게 참고
→ 단순한 부정 표현이 아니라 긍정 문맥으로 해석 가능
```

Attention을 출력하도록 모델을 불러올 수 있다.

```python
import torch
from transformers import (
    AutoTokenizer,
    AutoModel
)

model_name = (
    "distilbert-base-uncased-"
    "finetuned-sst-2-english"
)

tokenizer = AutoTokenizer.from_pretrained(
    model_name
)

model = AutoModel.from_pretrained(
    model_name,
    output_attentions=True
)
```

```python
sentence = "the concert was not boring at all"

inputs = tokenizer(
    sentence,
    return_tensors="pt"
)

with torch.no_grad():
    outputs = model(**inputs)
```

- 문장 전체의 토큰 관계를 계산
- 멀리 떨어진 단어도 직접 참고 가능
- 여러 Attention Head가 서로 다른 관계를 학습

```python
tokens = tokenizer.convert_ids_to_tokens(
```

- Attention Map은 모델의 모든 판단 근거를 완전히 설명하는 도구는 아님

11-1. Transformer의 기본 구조

```plain text
입력 문장
→ 토큰화
→ 임베딩
→ 위치 정보 추가
→ Self-Attention
→ Feed Forward Network
→ 출력
```

- 임베딩 : 토큰을 의미 벡터로 변환
- 위치 정보 : 문장 안에서 토큰의 순서 표현
- Self-Attention : 같은 문장 안의 토큰 관계 계산
- Feed Forward Network : 각 토큰의 표현을 추가로 변환
11-2. Encoder와 Decoder

```plain text
Encoder
→ 입력 문장을 이해하는 역할

Decoder
→ 앞의 출력과 입력 문맥을 이용해 다음 토큰 생성
```

- BERT 계열 : Encoder 중심
- GPT 계열 : Decoder 중심
- 번역 모델 : Encoder와 Decoder를 함께 사용할 수 있음

```python
output = gpt2.generate(

    pad_token_id=gpt2_tokenizer.eos_token_id

    )
)
```

```plain text
현재 문맥으로 다음 토큰 예측
→ 선택한 토큰을 문장에 추가
→ 추가된 문장으로 다시 예측
→ 반복
```

12-3. Temperature

**Temperature**

`생성할 토큰의 확률 분포를 조절하는 값`

```python
for temperature in [0.3, 1.2]:
    output = gpt2.generate(
        **inputs,
        max_new_tokens=20,
        do_sample=True,
        temperature=temperature,
        pad_token_id=gpt2_tokenizer.eos_token_id
    )

    print(
        temperature,
        gpt2_tokenizer.decode(output[0])
    )
```

```plain text
Temperature 낮음
→ 확률이 높은 단어를 주로 선택
→ 안정적이고 예측 가능한 문장

Temperature 높음
→ 다양한 단어를 선택
→ 창의적이지만 문장이 불안정할 수 있음
```

※ Temperature는 모델의 지식을 늘리는 값이 아니라 출력의 다양성을 조절하는 값

13-1. LLM

**LLM Large Language Model**

`매우 많은 텍스트와 파라미터를 이용해 언어 패턴을 학습한 대규모 언어 모델`

```plain text
작은 언어 모델
→ 제한된 패턴 학습

대규모 언어 모델
→ 더 많은 문맥과 표현 학습
→ 번역·요약·질의응답·생성 등 다양한 작업 수행
```

LLM은 사실을 데이터베이스에서 검색하는 방식이 아니라 문맥상 다음에 올 가능성이 높은 토큰을 예측한다.

```plain text
LLM의 출력
→ 확률적으로 자연스러운 문장

자연스러운 문장
≠ 항상 사실인 문장
```

13-2. Hallucination

**환각 Hallucination**

`모델이 사실이 아니거나 근거가 없는 내용을 그럴듯하게 생성하는 현상`

발생 원인

- 다음 토큰 확률을 기반으로 문장 생성
- 학습 데이터가 부족하거나 오래됨
- 질문의 문맥이 불명확함
- 모델이 실제 정보원을 조회하지 않음
※ 언어 모델의 결과는 사람이 검증해야 함

14-1. Hugging Face Hub

**Hugging Face Hub**

`다양한 사전학습 모델과 데이터셋을 공유하는 저장소`

사전학습 모델을 사용하면 대규모 데이터를 직접 수집하고 처음부터 학습하지 않아도 된다.

```plain text
직접 학습
→ 데이터 수집
→ 모델 설계
→ 대규모 학습
→ 평가와 배포

사전학습 모델
→ 목적에 맞는 모델 선택
→ 바로 추론 또는 추가 학습
```

14-2. Pipeline

**pipeline**

`토큰화, 모델 실행, 결과 변환 과정을 묶어 간단하게 사용할 수 있는 인터페이스`

```python
from transformers import pipeline

classifier = pipeline(
    "sentiment-analysis",
    model=(
        "distilbert-base-uncased-"
        "finetuned-sst-2-english"
    )
)
```

```python
print(
    classifier(
        "This song is a masterpiece!"
    )
)

print(
    classifier(
        "Worst title track ever."
    )
)
```

결과 예시 구조

```plain text
label
→ POSITIVE 또는 NEGATIVE

score
→ 해당 판정에 대한 모델의 확신도
```

※ `score`는 모델의 전체 정확도가 아니라 현재 판정에 대한 확신도

## 💭 오늘의 회고

- **배운 점**
- NLP : 사람의 언어를 컴퓨터가 이해하고 생성하게 하는 기술
- 컴퓨터는 문자를 숫자로 저장하지만 문자 코드만으로 의미를 이해하지 못함
- 감성 분석 : 문장의 감정을 긍정·부정 등으로 분류하는 작업
- 규칙 기반 감성 분석은 긍정·부정 단어의 개수로 판단
- 규칙 기반 방식은 신조어, 부정어, 반어법과 문맥 처리에 한계가 있음
- 토큰 : 언어 모델이 문장을 처리하는 기본 단위
- 토큰화 : 문장을 단어·문장부호·부분단어 등으로 나누는 과정
- `split()` : 공백 기준의 단순 토큰화
- `word_tokenize()` : 문장부호와 축약형까지 분리
- 불용어 : 자주 등장하지만 분석에서 핵심 의미가 적은 단어
- 감성 분석에서는 `not`처럼 의미를 뒤집는 불용어를 함부로 제거하면 안 됨
- 한국어는 조사와 어미 때문에 형태소 분석이 중요
- Subword Tokenization : 새로운 단어를 알고 있는 여러 조각으로 분해
- 토큰 수는 모델의 입력 길이와 API 사용량에 영향을 줌
- One-Hot Encoding은 단어의 구분만 가능하고 의미의 유사성은 표현하지 못함
- 임베딩 : 단어나 문장을 의미를 담은 벡터로 변환
- GloVe : 단어의 동시 등장 통계를 이용한 사전학습 임베딩
- 의미가 비슷한 단어는 임베딩 공간에서 가까운 위치에 존재
- 임베딩 벡터는 유사도 계산과 단어 관계 연산에 활용 가능
- PCA를 이용해 고차원 임베딩을 2차원으로 시각화할 수 있음
- Transformer : Attention을 이용해 문장 전체의 토큰 관계를 처리하는 구조
- Self-Attention : 같은 문장 안에서 각 토큰이 다른 토큰을 참고하는 방식
- BERT는 문장 이해에 강한 Encoder 계열 모델
- GPT는 다음 토큰을 예측하는 Decoder 계열 모델
- 다음 토큰 예측을 반복하면 문장을 생성할 수 있음
- Temperature가 낮으면 안정적이고 높으면 다양하지만 불안정한 문장 생성
- LLM은 사실 데이터베이스가 아니라 다음 토큰을 예측하는 확률 모델
- 자연스러운 답변이 항상 정확한 사실을 의미하지는 않음
- Hallucination : 모델이 근거 없는 내용을 그럴듯하게 생성하는 현상
- Hugging Face Hub : 공개 사전학습 모델과 데이터셋을 공유하는 저장소
- `pipeline()` : 토큰화, 모델 추론과 결과 변환을 간단하게 실행하는 인터페이스
- Pipeline의 `score`는 현재 판정에 대한 확신도이며 모델의 정확도가 아님
- 모델을 사용할 때 지원 언어, 학습 데이터와 한계를 확인해야 함
- 영어 전용 감성 분석 모델은 번역 모델과 연결해 한국어에 적용할 수 있음
- 여러 모델을 번역→분석처럼 연결해 하나의 서비스 흐름을 만들 수 있음
- 사전학습 모델은 규칙 기반보다 문맥을 잘 처리하지만 결과 검증은 여전히 필요
