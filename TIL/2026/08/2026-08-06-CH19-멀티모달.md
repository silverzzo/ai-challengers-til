# CH19 (멀티모달)

## 📝 오늘 배운 내용 요약

1-1. 멀티모달

**멀티모달 AI**

`텍스트뿐 아니라 이미지, 음성처럼 서로 다른 형태의 데이터를 함께 처리하는 AI`

```plain text
텍스트
이미지
음성
↓
하나의 AI 시스템에서 이해
↓
분류·검색·답변·생성
```

기존의 텍스트 전용 AI는 글자만 입력받지만 멀티모달 AI는 사진을 보고 음성을 들을 수 있다.

```plain text
멀티모달의 기본 실무 패턴

이미지·음성
→ 텍스트로 변환
→ 기존의 분류·RAG·LLM에 연결
```

3-1. Speech-to-Text

**음성 인식**

`음성 파일에 포함된 사람의 말을 텍스트로 변환하는 기술`

Whisper 모델을 이용해 음성 문의를 받아쓸 수 있다.

```python
from transformers import pipeline

transcriber = pipeline(
    "automatic-speech-recognition",
    model="openai/whisper-tiny"
)
```

```python
result = transcriber(
    "travel_inquiry.wav"
)

print(
    result["text"]
)
```

```plain text
고객 음성
→ Whisper
→ 텍스트 문의
→ 프롬프트·분류·RAG 처리
```

3-2. 모델 크기와 성능

```python
transcriber_base = pipeline(
    "automatic-speech-recognition",
    model="openai/whisper-base"
)
```

```python
print(
    "tiny:",
    transcriber(
        "travel_inquiry.wav"
    )["text"]

print(
    "base:",
    transcriber_base(
        "travel_inquiry.wav"
    )["text"]

```

- 작은 모델 : 빠르고 가벼움
- 큰 모델 : 상대적으로 정확하지만 느리고 무거움
```plain text
whisper-tiny
→ 빠름
→ 정확도가 낮을 수 있음

whisper-base
→ 상대적으로 느림
→ 받아쓰기 품질이 좋아질 수 있음
```

3-3. 음성 인식의 한계

- 주변 소음이 많으면 오류 발생
- 발음과 억양의 영향을 받음
- 전문 용어와 고유명사를 잘못 인식할 수 있음
- 지원 언어와 모델 크기에 따라 결과가 달라짐
※ 실제 서비스에서는 음성 인식 결과를 바로 실행하지 않고 사용자가 다시 확인하도록 만드는 것이 안전

4-1. Text-to-Image

**이미지 생성 AI**

`텍스트 프롬프트를 바탕으로 새로운 이미지를 생성하는 기술`

```plain text
텍스트 프롬프트
→ 이미지 생성 모델
→ 새로운 이미지
```

좋은 프롬프트에는 다음과 같은 정보가 포함될 수 있다.

- 주제
- 배경
- 구도
- 조명
- 분위기
- 스타일
- 제외할 요소
```plain text
단순한 프롬프트
→ 해변 그려줘

구체적인 프롬프트
→ 몰디브의 조용한 해변,
   이른 아침의 부드러운 햇빛,
   여행 광고 사진 스타일,
   사람과 글자는 제외
```

4-2. 프롬프트 구체성

```plain text
1단계
→ 산 그려줘

2단계
→ 단풍이 물든 설악산 울산바위

3단계
→ 이른 아침 안개와 필름 사진 스타일 추가

4단계
→ 등산객과 글자는 제외
```

프롬프트가 구체적일수록 생성 결과의 방향을 더 명확하게 제어할 수 있다.

5-1. Diffusion Model

**Diffusion Model**

`무작위 노이즈에서 시작해 노이즈를 단계적으로 제거하면서 이미지를 생성하는 모델`

```python
import numpy as np
from skimage import data

target = (
    data.astronaut()
    / 255.0
)

rng = np.random.default_rng(42)

noise = rng.random(
    target.shape
)
```

노이즈 비율을 줄이면서 이미지가 나타나는 과정을 시각화한다.

```python
ratios = np.linspace(
    1.0,
    0.0,
    5
)

plt.figure(figsize=(15, 3))

for i, ratio in enumerate(ratios):
    mixed = (
        ratio * noise
        + (1 - ratio) * target
    )

    plt.subplot(
        1,
        len(ratios),
        i + 1
    )

    plt.imshow(mixed)
    plt.axis("off")
    plt.title(
        f"노이즈 {ratio:.0%}"
    )

plt.show()
```

```plain text
100% 노이즈
→ 노이즈 예측
→ 노이즈 제거
→ 반복
→ 완성된 이미지
```

진짜 Diffusion 모델에서는 신경망이 현재 이미지의 노이즈를 예측하고 텍스트 프롬프트가 제거 방향을 조절한다.

5-2. Stable Diffusion


6-1. Agent

**AI Agent**

`질문을 분석하고 필요한 도구를 선택해 실행한 뒤 결과를 이용해 답변하는 AI 시스템`

```plain text
사용자 질문
→ 의도 판단
→ 도구 선택
→ 인자 추출
→ 도구 실행
→ 결과를 바탕으로 답변
```

순수 LLM은 학습 시점 이후의 실시간 정보를 알 수 없고 복잡한 계산을 틀릴 수 있다.

Agent는 외부 도구를 사용해 이러한 한계를 보완한다.

7-3. 계산기 도구

사용자 입력을 그대로 `eval()`에 전달하면 운영체제 명령이나 위험한 코드가 실행될 수 있다.

따라서 허용할 문자를 제한한다.

```python
import re

def calculator(expression):
    if not re.fullmatch(
        r"[0-9+\-*/().\s]+",
        expression
    ):
        return "허용되지 않은 수식입니다."

    return eval(
        expression,
        {"__builtins__": {}}
    )
```

```python
print(
    get_weather("방콕")
)

print(
    get_exchange_rate("유로")
)

print(
    calculator("1450 * 300")
)
```

```plain text
에이전트의 도구
→ 실제 시스템을 실행할 수 있음
→ 일반 프롬프트보다 보안이 더 중요
```

※ 가능한 경우 `eval()` 대신 안전하게 설계된 계산 라이브러리나 별도의 계산 API를 사용하는 것이 좋음

8-1. Router

**라우터 Router**

`사용자 질문에 어떤 도구가 필요한지 선택하는 구성 요소`

가장 단순한 방식은 질문 안의 특정 단어를 확인하는 것이다.

```python
def route_v01(question):
    if "날씨" in question:
        return "get_weather"

    elif "환율" in question:
        return "get_exchange_rate"

    elif "계산" in question:
        return "calculator"

    return "unknown"
```

```python
print(
    route_v01(
        "방콕 날씨 알려줘"
    )
)
```

9-1. Tool Specification

각 도구에 이름과 설명을 작성한다.

```python
tool_specs = {
    "get_weather": (
        "특정 도시의 현재 날씨, "
        "기온, 비 소식, 우산 필요 여부를 확인"
    ),

    "get_exchange_rate": (
        "달러, 유로, 엔 등 외화를 "
        "원화로 환산하거나 환율을 확인"
    ),

    "calculator": (
        "숫자의 덧셈, 뺄셈, 곱셈, "
        "나눗셈과 수식 계산"
    )
}
```

실제 Function Calling에서도 LLM에게 함수의 이름, 설명과 파라미터를 제공한다.

9-2. 도구 설명 임베딩

```python
from sentence_transformers import (
    SentenceTransformer
)

import numpy as np

embedding_model = SentenceTransformer(
    "paraphrase-multilingual-MiniLM-L12-v2"
)

tool_names = list(
    tool_specs.keys()
)

tool_descriptions = list(
    tool_specs.values()
)

tool_embeddings = (
    embedding_model.encode(
        tool_descriptions,
        normalize_embeddings=True
    )
)
```

9-3. 의미 기반 도구 선택

```python
def route_v10(question):
    question_embedding = (
        embedding_model.encode(
            [question],
            normalize_embeddings=True
        )[0]
    )

    scores = (
        tool_embeddings
        @ question_embedding
    )

    best_idx = np.argmax(scores)

    return (
        tool_names[best_idx],
        float(scores[best_idx])
    )
```

```python
print(
    route_v10(
        "방콕 갈 건데 우산 챙겨야 할까?"
    )
)
```

```plain text
질문과 도구 설명을 임베딩
→ 의미 유사도 계산
→ 가장 가까운 도구 선택
```

**Function Calling**

`LLM이 질문을 분석해 어떤 함수를 어떤 인자로 호출할지 구조화된 형태로 결정하는 기능`


10-2. 인자 추출

수업에서는 질문에서 인자를 규칙으로 추출한다.

```python
def extract_argument(
    question,
    tool
):
    if tool == "get_weather":
        return next(
            (
                city
                for city in [
                    "방콕",
                    "파리",
                    "몰디브"
                ]
                if city in question
            ),
            None
        )

    if tool == "get_exchange_rate":
        return next(
            (
                currency
                for currency in [
                    "달러",
                    "유로",
                    "엔"
                ]
                if currency in question
            ),
            None
        )

    if tool == "calculator":
        match = re.search(
            r"[0-9+\-*/().\s]+",
            question
        )

        if match:
            return match.group().strip()

    return None
```

실제 Function Calling에서는 LLM이 도구 선택과 인자 추출을 함께 수행한다.

```python
def travel_agent(question):
    tool, score = route_v10(
        question

    argument = extract_argument(
        question,
        tool

    result = TOOLS[tool](
        argument

        "score": score,
```

11-3. 실패 처리

인자를 찾지 못하거나 도구가 `"정보 없음"`을 반환할 수 있다.

```python
def travel_agent_safe(question):
    tool, score = route_v10(
        question
    )

    argument = extract_argument(
        question,
        tool
    )

    if argument is None:
        return (
            "필요한 도시, 통화 또는 "
            "계산식을 확인할 수 없습니다."
        )

    result = TOOLS[tool](
        argument
    )

    if result == "정보 없음":
        return (
            "현재 해당 정보를 "
            "제공하지 않습니다."
        )

    return result
```

12-1. Threshold

의미 기반 라우터는 어떤 질문이든 가장 가까운 도구 하나를 반환한다.

도구와 관계없는 질문에도 잘못된 도구를 선택할 수 있다.

```python
tool, score = route_v10(
    "몰디브 가면 뭐가 재밌어?"
)

print(tool, score)
```

따라서 최소 유사도 기준이 필요하다.

```python
TOOL_THRESHOLD = 0.35

tool, score = route_v10(question)

if score < TOOL_THRESHOLD:
    print(
        "도구를 사용하지 않습니다."
    )
```

```plain text
유사도 ≥ 임계값
→ 도구 질문으로 판단

유사도 < 임계값
→ 일반 답변 또는 RAG로 전달
```

12-2. 임계값 설정의 영향

```plain text
임계값이 너무 낮음
→ 정책 질문도 도구로 잘못 전달

임계값이 너무 높음
→ 실제 날씨 질문도 도구를 사용하지 못함
```

적절한 임계값은 여러 질문으로 실험해 결정해야 한다.

13-1. MCP

**MCP Model Context Protocol**

`AI 애플리케이션과 외부 도구·데이터를 일정한 방식으로 연결하기 위한 표준 규격`

서비스마다 서로 다른 방식으로 연결하면 연동 코드가 계속 증가한다.

```plain text
MCP 이전

AI 앱 A → 날씨 전용 연결
AI 앱 A → 호텔 전용 연결
AI 앱 B → 날씨 전용 연결
AI 앱 B → 호텔 전용 연결
```

MCP는 USB처럼 공통 규격을 제공한다.

```plain text
AI 앱
→ MCP Client
→ MCP Server
→ 외부 도구
```

13-2. MCP의 구성

```plain text

Server

```

14-1. 서버 클래스

```python
class ConciergeMCPServer:
    def __init__(self, name):
        self.name = name
        self.tools = {}

    def register_tool(
        self,
        name,
        function,
        description
    ):
        self.tools[name] = {
            "function": function,
            "description": description
        }

    def list_tools(self):
        return {
            name: info["description"]
            for name, info
            in self.tools.items()
        }

    def call_tool(
        self,
        tool_name,
        *args
    ):
        return self.tools[
            tool_name
        ]["function"](*args)
```

MCP 서버의 핵심 기능

```plain text
도구 등록
→ register_tool()

도구 목록 공개
→ list_tools()

표준 방식으로 실행
→ call_tool()
```

도구가 `N`개이고 AI 앱이 `M`개라면 다음과 같이 비교할 수 있다.

표준 실패 응답을 사용하면 안정적으로 처리할 수 있다.

```python
class ConciergeMCPServerV2(
    ConciergeMCPServer
):
    def call_tool(
        self,
        tool_name,
        *args
    ):
        if tool_name not in self.tools:
            return {
                "ok": False,
                "reason": "도구가 존재하지 않습니다."
            }

        try:
            result = self.tools[
                tool_name
            ]["function"](*args)

            return {
                "ok": True,
                "result": result
            }

        except Exception as error:
            return {
                "ok": False,
                "reason": str(error)
            }
```

```plain text
성공
→ {"ok": True, "result": ...}

실패
→ {"ok": False, "reason": ...}
```

표준 응답을 사용하면 Host가 서버마다 다른 오류 형식을 처리하지 않아도 된다.

```python
TOOL_THRESHOLD = 0.35

def concierge(
    question,
    image=None
):
    search_query = question

    # ① 이미지 이해
    if image is not None:
        caption = captioner(
            image
        )[0]["generated_text"]

        search_query = (
            question
            + "\n사진 설명: "
            + caption
        )

    # ② 도구 라우팅
    tool, score = route_v10(
        search_query
    )

    if score >= TOOL_THRESHOLD:
        argument = extract_argument(
            search_query,
            tool
        )

        if argument is not None:
            return {
                "route": "tool",
                "tool": tool,
                "result": TOOLS[tool](
                    argument
                )
            }

    # ③ FAQ 검색
    query_embedding = (
        embedding_model.encode(
            [search_query],
            normalize_embeddings=True
        )
        .astype("float32")
    )

    similarities, indices = (
        faq_index.search(
            query_embedding,
            k=1
        )
    )

    faq = travel_faq[
        indices[0][0]
    ]

    return {
        "route": "faq",
        "source": faq
    }
```

MCP 서버가 제공하는 도구 목록을 이용해 라우터를 자동으로 구성할 수 있다.

```python
def build_router_from_servers(
    servers
):
    specs = {}
    functions = {}

    for server in servers:
        for tool_name, description in (
            server.list_tools().items()
        ):
            specs[tool_name] = description

            functions[tool_name] = (
                server.tools[
                    tool_name
                ]["function"]
            )

    return specs, functions
```

## 💭 오늘의 회고

- **배운 점**
- 멀티모달 AI : 텍스트, 이미지와 음성을 함께 처리하는 AI
- 이미지 캡셔닝 : 이미지 내용을 자연어 문장으로 설명
- 이미지 분류 : 이미지를 미리 정한 클래스로 구분
- 멀티모달 실무에서는 이미지와 음성을 텍스트로 변환해 기존 NLP 구조에 연결할 수 있음
- Whisper : 음성을 텍스트로 변환하는 음성 인식 모델
- 모델이 클수록 품질이 좋아질 수 있지만 속도와 메모리 비용도 증가
- 이미지 생성 AI는 텍스트 프롬프트를 바탕으로 새로운 이미지를 생성
- 구체적인 프롬프트에는 주제, 배경, 분위기, 스타일과 제외 조건이 포함될 수 있음
- Negative Prompt : 이미지에서 제외할 요소를 지정
- Diffusion : 노이즈에서 시작해 단계적으로 노이즈를 제거하며 이미지 생성
- Stable Diffusion은 GPU 사용이 권장되는 이미지 생성 모델
- AI Agent : 질문을 판단해 외부 도구를 선택하고 실행하는 시스템
- Agent는 실시간 정보 조회와 정확한 계산에 활용 가능
- 에이전트는 실제 도구를 실행하므로 입력 검증과 권한 관리가 중요
- Router : 질문에 필요한 도구를 선택하는 구성 요소
- 키워드 라우터는 정해진 단어가 없으면 의도를 찾기 어려움
- 의미 기반 라우터는 질문과 도구 설명을 임베딩해 가장 가까운 도구 선택
- Tool Specification : 도구 이름, 설명과 파라미터를 정의한 명세
- Function Calling : LLM이 호출할 함수와 인자를 구조화된 형태로 결정
- Agent Loop : 판단 → 도구 선택 → 인자 추출 → 실행 → 답변
- 유사도 임계값은 관련 없는 질문의 도구 호출을 방지
- 임계값이 너무 낮으면 오호출이 많고 너무 높으면 필요한 도구를 놓칠 수 있음
- MCP : AI 앱과 외부 도구를 공통 규격으로 연결하는 프로토콜
- MCP Host : 사용자와 대화하는 AI 앱
- MCP Client : Host와 Server 사이의 표준 통신 담당
- MCP Server : 도구 목록과 실행 기능을 표준 형식으로 제공
- `register_tool()` : MCP 서버에 도구 등록
- `list_tools()` : 서버가 제공하는 도구 목록 공개
- `call_tool()` : 표준 방식으로 도구 실행
- MCP를 사용하면 새로운 서버를 연결해 도구를 쉽게 확장할 수 있음
- 개별 연동은 `N×M`, MCP 구조는 `N+M` 형태로 연결 수를 줄일 수 있음
- 표준 성공·실패 응답을 사용하면 오류 처리 방식도 통일 가능
- 실시간 정보와 계산은 Agent, 사내 정책과 FAQ는 RAG가 적합
- 여행 컨시어지는 사진 캡셔닝, 음성 인식, 의미 라우터, Agent와 RAG를 하나로 연결
- 음성 컨시어지는 `음성 → 받아쓰기 → 라우팅 → 도구·RAG` 순서로 동작
- MCP 메뉴판에서 도구 명세를 자동 생성하면 서버 추가 시 라우터도 자동으로 확장 가능
- 멀티모달 Agent는 각 단계의 오류가 다음 단계로 전달될 수 있으므로 중간 결과 검증이 중요
- 확실하지 않은 경우 도구를 실행하지 않고 사용자에게 추가 정보를 요청하는 것이 안전
