## 💭 오늘의 회고

1. **배운 점**
- `np.array()`로 배열 생성, `shape`/`ndim`/`dtype`/`size`로 속성 확인 — 배열은 **동일 자료형**만 저장
- 인덱싱/슬라이싱: 1차원은 `arr[i]`, 2차원은 `arr[행, 열]` (`:`는 "전부")
- 배열의 `+`, 는 리스트와 달리 실제 수학 연산 (같은 위치끼리 계산) — 환율, 할인, 수익률이 한 줄로
- 통계: `mean()`/`sum()`/`max()`/`min()`/`std()` + 위치를 찾는 `argmax()`/`argmin()`
- **axis=0은 ↓열별, axis=1은 →행별** — 결과 개수로 검산하는 습관
- 불리언 인덱싱 `arr[arr > 값]` = 조건으로 골라내기 — 다음 시간 Pandas 필터링의 원리
- `np.where(조건, 참값, 거짓값)` = 조건에 따라 값 바꾸기
- `np.sort()` 정렬, `reshape()` 모양 변경 (요소 개수 유지)
- 정렬: `sort_values("컬럼", ascending=False)` — 원본은 그대로, 결과는 변수에 담기
- **여러 값 비교 + 범위 조건 필터링**
```python
# 틀린 방식 (콤마는 튜플을 만들어버림)
df[(df['도시']=='서울','인천') & (25<= df['나이']<=35)]

# 정석
df[df['도시'].isin(['서울', '인천']) & (25 <= df['나이']) & (df['나이'] <= 35)]
```

- 여러 값 중 하나라도 일치하는지 볼 땐 `.isin(['값1', '값2'])`을 씀
- 범위 조건(`25 ≤ 나이 ≤ 35`)은 파이썬처럼 연쇄로 못 쓰고, `(조건1) & (조건2)`로 쪼개서 씀
- 조건식만 단독으로 쓰면 True/False만 나옴 (불리언 인덱싱)
```python
df['현재가'] >= 150        # True/False로 이루어진 Series만 반환 (필터링 X)
df[df['현재가'] >= 150]    # df[] 안에 넣어야 실제 데이터가 걸러짐
```

2. **어려운 점/개선할 점**
- **리스트 vs NumPy 배열 인덱싱 방식 혼동**: `[1, 2]`와 `[1][2]`가 결과는 같아 보여도 내부 동작이 다르다는 걸 직관적으로 구분하지 못함. → 다차원 인덱싱은 `arr[행, 열]` 형태를 기본으로 쓰는 습관 필요함.
- **괄호 기호별 역할 혼동**: f-string 안에서 `{days{best}}`처럼 중괄호를 겹쳐 써서 `SyntaxError`를 겪음. 값을 꺼내는 대괄호 `[]`와 문자열 포매팅용 중괄호 `{}`를 헷갈림. → f-string 안에 인덱싱/함수 호출을 넣을 땐 `{days[best]}`처럼 괄호 종류를 명확히 구분해서 쓰기.
- **중첩된 코드 해석**: `days[cafe.argmax()]`처럼 인덱싱 안에 함수 호출이 통째로 들어간 구조:  중첩 코드는 가장 안쪽 함수/연산부터 계산 → 그 결과가 바깥 인덱싱에 사용됨
- **prices[1][2] vs prices[1, 2] 비효율성 인지 부족**: 대괄호를 두 번 쓰면 임시 배열이 한 번 더 생성되어 비효율적이라는 걸 모르고 습관적으로 리스트 방식(`[1][2]`)을 쓰려 함. → NumPy 배열에서는 콤마 인덱싱을 기본값으로 쓰는 습관 필요함.
- **len(배열[조건])과 (조건).sum()의 내부 차이 **: 둘 다 같은 결과(개수)를 내지만 메모리/속도 면에서 다름. (**실제 필터링된 값 자체가 필요할 때**는 `배열[조건]`을 쓰는 게 맞고, **개수만 필요할 때**는 `.sum()`이 더 효율적) 
- **콤마(,)와 OR 조건 혼동**: 여러 값을 비교할 때 파이썬 리스트/튜플 감각으로 콤마를 써버려서 의도와 다르게 튜플이 만들어짐. → 열 안에서 여러 값 비교는 무조건 `.isin()`을 먼저 떠올리는 습관 필요함.
- **연쇄 비교 문법을 판다스에도 그대로 적용하려 함**: `25 <= df['나이'] <= 35`처럼 파이썬 기본 문법을 Series에 그대로 써서 에러남. → Series 조건은 항상 "조건 하나당 괄호 하나 + `&`/`|`로 연결"이 기본이라는 걸 규칙화하기.
- **조건식과 필터링 결과를 혼동**: `df['현재가'] >= 150`만 실행하고 왜 실제 값이 안 나오냐고 헷갈림. → "조건식 = 기준표(True/False)", "`df[조건식]` = 실제 데이터"라는 2단계 구조를 항상 의식하기.
- `idxmax()`**가 값이 아니라 인덱스라는 걸 놓침**: `idxmax()` 결과를 값처럼 바로 출력하려다 원하는 데이터가 안 나옴. → `idxmax()`는 "위치(인덱스)를 찾는 함수"이고, 실제 값을 보려면 `.loc[]`으로 한 번 더 감싸야 한다는 걸 기억하기.
- `print(A, B)`** 형태로 여러 정보를 한 번에 뽑으려다 원하는 결과와 다르게 나옴**: 열 전체와 인덱스 번호가 따로 출력되는 걸 보고 왜 안 되는지 헷갈림. → 정확히 한 값만 필요하면 `.loc[행, 열]`처럼 하나의 인덱싱 표현으로 합쳐서 뽑는 습관 필요함.
