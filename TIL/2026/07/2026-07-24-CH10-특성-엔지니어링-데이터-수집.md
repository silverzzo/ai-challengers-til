# CH10 (특성 엔지니어링 / 데이터 수집)

## 📝 오늘 배운 내용 요약

1-1. 인코딩

- **인코딩**
`문자로 된 범주형 데이터 → 머신러닝 모델이 계산할 수 있는 숫자로 변환`

머신러닝 모델은 `"전자기기"`, `"생활용품"` 같은 문자 자체를 계산할 수 없기 때문에 숫자로 바꿔줘야 한다.

```python
print(df["카테고리"].unique())

# ['전자기기', '생활용품', '패션']
```

- 범주형 데이터 : 정해진 종류나 그룹을 나타내는 데이터
- 인코딩 : 범주형 데이터를 숫자로 변환하는 과정
- 변환 방식에 따라 모델이 데이터의 의미를 다르게 이해할 수 있음
※ 순서가 없는 데이터를 단순히 `0, 1, 2`로 변환하면 모델이 숫자 크기에 의미가 있다고 오해할 수 있음

1-2. Label Encoding

- **Label Encoding**
`각 범주에 하나의 정수 번호를 부여하는 방법`

```python
from sklearn.preprocessing import LabelEncoder
	
encoder = LabelEncoder()

df["카테고리_label"] = encoder.fit_transform(df["카테고리"])

print(encoder.classes_)
print(df[["카테고리", "카테고리_label"]].head())
```

- `fit()` : 어떤 범주가 존재하는지 학습
- `transform()` : 학습한 범주를 숫자로 변환
- `fit_transform()` : 학습과 변환을 한 번에 수행
- `classes_` : 범주에 번호가 부여된 순서 확인
- 컬럼 수가 늘어나지 않음
예시

```plain text
생활용품 → 0
전자기기 → 1
패션 → 2
```

하지만 위 숫자는 단순한 이름표일 뿐이다.

`패션 2 > 전자기기 1`이라는 의미는 아님

따라서 Label Encoding은 주로 다음과 같은 경우에 사용한다.

- 순서가 있는 범주
- 머신러닝의 정답 `y`
- 범주 간 순서를 모델이 고려해도 되는 경우
1-3. 순서가 있는 범주 변환

- 범주에 실제 순서가 있다면 `map()`을 사용해 직접 번호를 지정할 수 있다.
```python
grade_order = {
    "하": 0,
    "중": 1,
    "상": 2
}

df["등급_encoded"] = df["등급"].map(grade_order)
```

```plain text
하 < 중 < 상
0  < 1  < 2
```

이 경우에는 숫자의 크기가 실제 범주의 순서를 나타낸다.

※ 순서가 있는 범주를 **순서형 범주**라고 함

1-4. One-Hot Encoding

- **One-Hot Encoding**
`범주마다 새로운 컬럼을 만들고 해당 여부를 0과 1로 표시하는 방법`

```python
encoded_df = pd.get_dummies(
    df,
    columns=["카테고리"],
    dtype=int
)

print(encoded_df.head())
```

변환 전

```plain text
카테고리
전자기기
패션
생활용품
```

변환 후

```plain text
카테고리_생활용품  카테고리_전자기기  카테고리_패션
        0                 1              0
        0                 0              1
        1                 0              0
```

- 범주 사이에 잘못된 숫자 순서가 생기지 않음
- 순서가 없는 명목형 데이터에 적합
- 범주가 많으면 생성되는 컬럼 수도 많아짐
```python
encoded_df = pd.get_dummies(
    df,
    columns=["카테고리", "결제수단"],
    drop_first=True,
    dtype=float
)
```

- `columns` : 인코딩할 컬럼 지정
- `drop_first=True` : 각 범주의 첫 번째 컬럼 생략
- `dtype=float` : 결과를 `0.0`, `1.0` 형태로 변환
1-5. 새로운 범주 처리

- 모델을 학습한 뒤 기존에 없던 새로운 범주가 들어올 수 있다.
```python
from sklearn.preprocessing import OneHotEncoder

encoder = OneHotEncoder(
    handle_unknown="ignore",
    sparse_output=False
)

train_encoded = encoder.fit_transform(train[["카테고리"]])
test_encoded = encoder.transform(test[["카테고리"]])
```

- `handle_unknown="ignore"` : 학습할 때 없던 범주가 들어와도 오류를 발생시키지 않음
- 훈련 데이터는 `fit_transform()`
- 테스트 데이터는 `transform()`만 사용
※ 테스트 데이터에 다시 `fit()`하면 훈련 데이터와 범주 기준이 달라질 수 있음

1-6. Label Encoding과 One-Hot Encoding

```plain text
범주에 순서가 있는가?
→ Label Encoding 또는 map()

범주에 순서가 없는가?
→ One-Hot Encoding

예측해야 하는 정답 y인가?
→ Label Encoding 사용 가능

새로운 범주가 들어올 가능성이 있는가?
→ OneHotEncoder의 handle_unknown 사용
```

2-1. 스케일링

- **스케일링**
`값의 범위가 서로 다른 수치형 특성을 비슷한 크기로 맞추는 과정`

예를 들어 다음 두 특성은 숫자의 범위가 크게 다르다.

```plain text
수량 : 1~60
단가 : 7,500~89,000
```

이 값을 그대로 사용하면 단가의 숫자가 훨씬 크기 때문에 모델이 단가를 더 중요하게 판단할 수 있다.

```python
print(df[["수량", "단가"]].describe())
```

스케일링은 특히 다음 모델에서 중요하다.

- KNN처럼 거리를 계산하는 모델
- 경사하강법을 사용하는 모델
- 로지스틱 회귀
- 신경망
- SVM
※ 스케일링은 데이터의 단위와 범위를 바꾸지만 데이터의 순서나 관계를 없애지는 않음

2-2. MinMaxScaler

- **MinMaxScaler**
`가장 작은 값을 0, 가장 큰 값을 1로 변환`

```python
from sklearn.preprocessing import MinMaxScaler

scaler = MinMaxScaler()

df["단가_mm"] = scaler.fit_transform(df[["단가"]])

print(df[["단가", "단가_mm"]].head())
```

계산 원리

```plain text
(현재값 - 최솟값) / (최댓값 - 최솟값)
```

- 결과가 일반적으로 `0~1` 범위로 변환
- 값의 범위를 정확히 제한하고 싶을 때 사용
- 최솟값과 최댓값을 기준으로 계산
- 이상치에 민감함
```plain text
정상 데이터 : 1, 2, 3, 4, 5
이상치 포함 : 1, 2, 3, 4, 5, 60
```

60이 최댓값이 되면 정상적인 `1~5` 값이 0 근처에 몰리게 된다.

2-3. StandardScaler

- **StandardScaler**
`데이터의 평균을 0, 표준편차를 1로 맞추는 방법`

```python
from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()

df["평점_std"] = scaler.fit_transform(
    df[["배송평점"]]
)

print(df["평점_std"].mean())
print(df["평점_std"].std())
```

계산 원리

```plain text
(현재값 - 평균) / 표준편차
```

- 평균과 비교해 값이 얼마나 떨어져 있는지 나타냄
- 평균과 같은 값은 약 `0`
- 평균보다 크면 양수
- 평균보다 작으면 음수
- 회귀 모델이나 딥러닝에서 자주 사용
- 이상치가 있으면 평균과 표준편차가 영향을 받을 수 있음
예시

```plain text
평균 키 : 170
표준편차 : 10

키 170 → 0
키 180 → 1
키 160 → -1
```

2-4. RobustScaler

- **RobustScaler**
`중앙값과 IQR을 기준으로 값을 변환하는 방법`

```python
from sklearn.preprocessing import RobustScaler

scaler = RobustScaler()

df["수량_robust"] = scaler.fit_transform(
    df[["수량"]]
)
```

- 중앙값을 기준으로 변환
- IQR을 사용해 데이터의 범위를 조정
- 평균이나 최댓값을 사용하지 않음
- 이상치의 영향을 비교적 적게 받음
**IQR**

`3사분위수 Q3 - 1사분위수 Q1`

데이터에 극단적인 이상치가 많다면 MinMaxScaler나 StandardScaler보다 RobustScaler가 적합할 수 있다.

2-5. 스케일러 비교

```plain text
값의 범위를 0~1로 만들고 싶은가?
→ MinMaxScaler

일반적인 회귀·분류 모델에 적용하는가?
→ StandardScaler

이상치가 많이 포함되어 있는가?
→ RobustScaler
```

2-6. fit과 transform

```python
scaler = StandardScaler()

train_scaled = scaler.fit_transform(train[["단가"]])
test_scaled = scaler.transform(test[["단가"]])
```

- `fit()` : 훈련 데이터의 평균, 표준편차 등의 기준을 계산
- `transform()` : 계산된 기준으로 데이터를 변환
- `fit_transform()` : 기준 계산과 변환을 동시에 수행
```plain text
훈련 데이터
→ fit_transform()

테스트 데이터
→ transform()
```

테스트 데이터에는 반드시 훈련 데이터에서 구한 기준을 사용해야 한다.

```python
# 잘못된 방법
test_scaled = scaler.fit_transform(test[["단가"]])
```

테스트 데이터에 다시 `fit()`하면 테스트 데이터의 정보를 미리 사용하는 **데이터 누수**가 발생할 수 있다.

※ 스케일링은 단가, 수량, 거리처럼 크기 자체에 의미가 있는 수치형 데이터에 적용

※ One-Hot Encoding으로 만들어진 `0/1` 컬럼은 일반적으로 스케일링하지 않음

3-1. 웹크롤링

- **웹크롤링**
`웹페이지에 접속 → HTML을 가져옴 → 필요한 정보를 추출 → 데이터로 저장`

웹사이트에서 제목, 가격, 평점처럼 반복되는 정보를 자동으로 수집하는 방법이다.

```python
import requests

url = "https://books.toscrape.com/catalogue/category/books/mystery_3/index.html"

response = requests.get(url)

print(response.status_code)
```

- `requests.get()` : 웹페이지에 GET 요청을 보냄
- `status_code` : 요청 성공 여부 확인
- `200` : 정상적으로 요청 성공
- `403` : 접근 거부
- `404` : 페이지를 찾을 수 없음
- `500` : 서버 내부 오류
※ HTML을 분석하기 전에 상태 코드가 `200`인지 먼저 확인하는 습관이 필요

3-2. HTML 파싱

- **파싱**
`HTML 문서를 읽고 필요한 정보를 찾기 쉬운 구조로 변환하는 과정`

```python
from bs4 import BeautifulSoup

soup = BeautifulSoup(
    response.text,
    "html.parser"
)
```

- `response.text` : 서버에서 받은 HTML 문자열
- `BeautifulSoup` : HTML을 분석할 수 있는 객체로 변환
- `"html.parser"` : HTML 해석 방법
책 한 권의 HTML 구조는 다음과 같이 구성될 수 있다.

```plain text
article
 ├── h3
 │    └── a : 제목과 링크
 ├── p.price_color : 가격
 ├── p.instock.availability : 재고
 └── p.star-rating : 평점
```

3-3. 원하는 태그 찾기

```python
first_book = soup.find(
    "article",
    class_="product_pod"
)

title = first_book.h3.a["title"]

price = first_book.select_one(
    "p.price_color"
).text

availability = first_book.select_one(
    "p.instock.availability"

```

- `find()` : 조건에 맞는 첫 번째 태그 반환
- `find_all()` : 조건에 맞는 모든 태그 반환
- `select_one()` : CSS 선택자와 일치하는 첫 번째 태그 반환
- `select()` : CSS 선택자와 일치하는 모든 태그 반환
- `.text` : 태그 안의 글자 추출
- `["title"]` : 태그의 속성값 추출
- `.strip()` : 앞뒤 공백과 줄바꿈 제거
```python
books = soup.find_all(
    "article",
    class_="product_pod"
)

print(len(books))
```

3-4. 한 페이지의 데이터 추출

반복되는 추출 작업은 함수로 만들어 사용한다.

```python
def parse_page(soup):
    rows = []

    books = soup.select("article.product_pod")

    for book in books:
        title = book.h3.a["title"]

        price_text = book.select_one(
            "p.price_color"
        ).text

        availability = book.select_one(
            "p.instock.availability"
        ).text.strip()

        rating_class = book.select_one(
            "p.star-rating"
        )["class"]

        rating = rating_class[1]

        rows.append({
            "제목": title,
            "가격": price_text,
            "재고": availability,
            "평점": rating
        })

    return rows
```

```plain text
HTML에서 책 태그 찾기
→ 책마다 제목·가격·재고·평점 추출
→ 딕셔너리로 만들기
→ 리스트에 추가
```

함수로 만들면 페이지가 바뀌어도 같은 코드를 재사용할 수 있다.

3-5. 페이지네이션

- **페이지네이션**
`여러 페이지로 나누어진 데이터를 다음 페이지로 이동하며 수집하는 방식`

```python
next_link = soup.select_one("li.next a")

if next_link:
    print(next_link["href"])
```

다음 페이지 링크가 존재하는 동안 반복한다.

```python
import time
from urllib.parse import urljoin

all_books = []
page_url = url

while True:
    response = requests.get(page_url)
    response.encoding = "utf-8"

    if response.status_code != 200:
        break

    page_soup = BeautifulSoup(
        response.text,
        "html.parser"
    )

    all_books.extend(parse_page(page_soup))

    next_a = page_soup.select_one("li.next a")

    if next_a is None:
        break

    page_url = urljoin(
        page_url,
        next_a["href"]
    )

    time.sleep(1)
```

- `extend()` : 추출된 여러 데이터를 기존 리스트에 이어 붙임
- `urljoin()` : 현재 주소와 상대 경로를 합쳐 완전한 URL 생성
- 다음 링크가 없으면 반복 종료
- `time.sleep()` : 요청 사이에 간격을 둠
※ 페이지 수를 직접 지정하는 것보다 다음 링크가 존재하는지를 기준으로 반복하는 것이 안전함

4-1. API

- **API**
`프로그램끼리 정해진 규칙에 따라 데이터를 주고받는 통로`

웹크롤링은 HTML 화면에서 직접 정보를 찾지만, API는 필요한 데이터를 정해진 형식으로 제공한다.

```plain text
사용자가 요청 전송
→ 서버가 요청 처리
→ JSON 형태로 결과 반환
```

예시

```python
import requests

url = "https://geocoding-api.open-meteo.com/v1/search"

params = {
    "name": "Seoul",
    "count": 1,
    "language": "en",
    "format": "json"
}

response = requests.get(
    url,
    params=params
)

print(response.status_code)
```

- `url` : 요청을 보낼 API 주소
- `params` : API에 전달할 조건
- `requests`가 딕셔너리를 쿼리스트링으로 변환해 URL에 추가
```plain text
?name=Seoul&count=1&language=en
```

4-2. JSON

- **JSON**
`키와 값의 구조로 데이터를 표현하는 형식`

```json
{
  "name": "Seoul",
  "latitude": 37.566,
  "longitude": 126.978
}
```

API의 JSON 응답은 `response.json()`을 사용해 파이썬 자료형으로 변환한다.

```python
data = response.json()

print(type(data))
print(data["results"][0])
```

```python
seoul_lat = data["results"][0]["latitude"]
seoul_lon = data["results"][0]["longitude"]

print(seoul_lat, seoul_lon)
```

- JSON 객체 `{}` → 파이썬 딕셔너리
- JSON 배열 `[]` → 파이썬 리스트
- 딕셔너리는 키를 이용해 값에 접근
- 리스트는 인덱스를 이용해 값에 접근
```plain text
data["results"]    → 검색 결과 리스트
data["results"][0] → 첫 번째 검색 결과
["latitude"]       → 위도 값
```

4-5. 함수로 여러 도시 조회

반복되는 API 요청은 함수로 만든다.

```python
def get_current_temp(city):
    geo_url = (
        "https://geocoding-api.open-meteo.com/v1/search"
    )

    geo_data = requests.get(
        geo_url,
        params={
            "name": city,
            "count": 1
        }
    ).json()

    lat = geo_data["results"][0]["latitude"]
    lon = geo_data["results"][0]["longitude"]

    weather_url = (
        "https://api.open-meteo.com/v1/forecast"
    )

    weather_data = requests.get(
        weather_url,
        params={
            "latitude": lat,
            "longitude": lon,
            "current": "temperature_2m"
        }
    ).json()

    return weather_data["current"]["temperature_2m"]
```

```python
cities = ["Seoul", "Busan", "Jeju"]

rows = []

for city in cities:
    temperature = get_current_temp(city)

    rows.append({
        "도시": city,
        "현재기온": temperature
    })

city_df = pd.DataFrame(rows)
```

4-6. GET과 POST

- GET : 서버에서 데이터를 받아올 때 사용
- POST : 서버에 새로운 데이터를 전달하거나 생성할 때 사용
```python
new_post = {
    "title": "실습용 제목",
    "body": "실습용 내용",
    "userId": 1
}

response = requests.post(
    "https://jsonplaceholder.typicode.com/posts",
    json=new_post
)

print(response.status_code)
print(response.json())
```

- `200` : 요청 성공
- `201` : 새로운 데이터 생성 성공
- `json=new_post` : 파이썬 딕셔너리를 JSON 형태로 전송

5-1. robots.txt

- **robots.txt**
`웹사이트에서 크롤러가 접근할 수 있는 경로와 접근하면 안 되는 경로를 알려주는 규칙 파일`

일반적으로 웹사이트의 최상위 경로에 위치한다.

```plain text
https://example.com/robots.txt
```

```python
import requests

robots_url = "https://books.toscrape.com/robots.txt"

response = requests.get(robots_url)

print(response.status_code)
print(response.text)
```

크롤링이 기술적으로 가능하더라도 반드시 허용된다는 의미는 아니다.

```plain text
기술적으로 접근 가능
≠ 자유롭게 수집 가능
```

5-2. robots.txt 구조

```plain text
User-agent: *
Disallow: /private/
Allow: /public/
Crawl-delay: 2
```

- `User-agent` : 규칙을 적용할 크롤러
-  : 모든 크롤러
- `Disallow` : 접근을 허용하지 않는 경로
- `Allow` : 접근을 허용하는 경로
- `Crawl-delay` : 요청 사이에 두어야 하는 대기 시간
예시

```plain text
User-agent: *
Disallow: /
Allow: /$
```

- 모든 크롤러에 적용
- 전체 경로 크롤링 금지
- 메인 페이지는 예외적으로 허용
5-3. 파이썬으로 접근 가능 여부 확인

```python
from urllib.robotparser import RobotFileParser

rp = RobotFileParser()

rp.set_url(
    "https://books.toscrape.com/robots.txt"
)

rp.read()

url = (
    "https://books.toscrape.com/"
    "catalogue/page-1.html"
)

print(rp.can_fetch("*", url))
```

- `set_url()` : robots.txt 주소 지정
- `read()` : robots.txt 내용 읽기
- `can_fetch()` : 특정 URL을 크롤링할 수 있는지 확인
- 결과가 `True`면 접근 허용
- 결과가 `False`면 접근 금지
```python
if rp.can_fetch("*", url):
    response = requests.get(url)
    print(response.status_code)
else:
    print("크롤링이 허용되지 않은 경로입니다.")
```

5-4. 서버에 부담 주지 않기

짧은 시간에 너무 많은 요청을 보내면 서버에 부담을 줄 수 있다.

```python
import time

for page in pages:
    response = requests.get(page)

    # 다음 요청 전 1초 대기
    time.sleep(1)
```

다음과 같은 방식은 피해야 한다.

```python
# 대기 없이 많은 요청을 반복
# for i in range(1000):
#     requests.get(url)
```

- 요청 사이에 적절한 간격 두기
- 필요한 데이터만 수집하기
- 같은 페이지를 불필요하게 반복 요청하지 않기
- 동시에 여러 크롤러를 실행하지 않기
5-5. 크롤링 시 확인할 사항

```plain text
robots.txt에서 허용하는가?
→ 이용약관에서 금지하지 않는가?
→ 개인정보가 포함되어 있지 않은가?
→ 저작권이 있는 콘텐츠를 무단 배포하지 않는가?
→ 서버에 과도한 요청을 보내지 않는가?
```

- 이용약관 확인
- 개인정보 수집 주의
- 저작권 보호
- 수집 목적과 사용 범위 확인
- 로그인이나 보안 장치를 우회하지 않기
- 수집한 데이터를 무단으로 재판매하거나 배포하지 않기
※ robots.txt가 허용한다고 해서 모든 법적·윤리적 문제가 해결되는 것은 아님

※ robots.txt는 웹사이트 운영자의 요청을 나타내는 규칙이며 기본적으로 준수해야 함
